Cutting a website's carbon footprint comes down to moving fewer bytes to each visitor, serving them from renewable-powered infrastructure, and running less code on the device at the other end. In our audit of [100 UK small-business homepages](/blog/we-audited-100-uk-small-business-websites/), the median page emitted 0.24 g of CO2e per view, 44% rated E or F, and the heaviest was nine hundred times dirtier than the lightest. These nine changes, ranked by how many grams per view they saved on real builds and under the [Sustainable Web Design Model](https://sustainablewebdesign.org/estimating-digital-emissions/), are the shortest route to a cleaner page.

## 1. Move to verified green hosting

The biggest single lever, because it changes the grid-intensity multiplier that sits under every other number. The Sustainable Web Design Model (v4) multiplies data-centre energy by `(1 - Green Hosting Factor)`, which zeros out the data-centre share of your emissions when the host is on The Green Web Foundation's verified list.

In practice that's a 25-40% cut on a typical page: data centres are one leg of the three-legged stool and the network and user device still run on the grid. It's still the largest single-move win, and it's a one-day change with no re-engineering.

How to do it:

- Check your current host on the [Green Web Foundation directory](https://www.thegreenwebfoundation.org/green-web-check/).
- If it fails, move. Cloudflare Pages (free), Netlify, Vercel and UK-based Krystal all pass.
- If you'd rather not touch it, our [managed green hosting](/services/green-web-hosting/) handles the migration and keeps it on verified renewable infrastructure.

## 2. Resize and reformat your images

Images were 60.5% of all bytes in our 100-site audit, and 44 of those 99 sites shipped more than 1 MB of imagery on the homepage alone. If one change halves the weight of a page, this is it.

The compounding wins:

- **Modern formats.** Export AVIF with a WebP fallback, JPEG last. [web.dev's image learn module](https://web.dev/learn/images) explains how a `<picture>` element lets the browser pick the first format it supports without downloading the others. AVIF is typically around half the file size of JPEG at the same perceptual quality.
- **Size for how they're displayed.** Stop serving a 4,000-pixel-wide hero to a 390-pixel-wide phone.
- **Responsive `srcset`.** Let the browser pick the smallest file that will do.
- **Width and height on every `<img>` and `<source>`.** No layout shift, no byte cost.

On [The Magpie's Tale](/portfolio/the-magpies-tale/), the independent bookshop site we built in Southport, every illustration is a hand-drawn image saved as WebP: 17 to 65 KB each. The site is rated A+ at 0.034 g of CO2e per view, cleaner than 96% of pages tested.

## 3. Drop autoplaying hero videos

Video and audio were 15.7% of all bytes in our study, almost entirely in the heaviest handful of sites. Every page over 8 MB in our sample had an autoplaying hero video on it. It's the single most expensive design choice on the modern web.

If you need the motion, in order of preference:

- A looping CSS animation or SVG, not video.
- A static poster image with a play button that fetches the file only on click.
- If it must autoplay, export it at the dimensions it will play at (a phone does not need 1080p), compress hard, mute it, and lazy-load below the fold.

## 4. Lazy-load everything below the fold

Native lazy-loading is one attribute: `loading="lazy"` on an image tag (and the same on an inline frame). The browser defers the request until the image is near the viewport, which means a visitor who leaves without scrolling never downloads it.

Set it on every image that isn't visible in the first screen. Leave it off the hero image so Largest Contentful Paint stays fast.

## 5. Subset your web fonts

Fonts were 9.6% of bytes in our audit, and 43 of 99 sites loaded more than 200 KB of font files, several more than their HTML, CSS and JavaScript combined. All usually for text that would read identically in a system font.

Cuts, in order:

- **Subset to the characters you actually need.** A UK English site has no use for Cyrillic, Vietnamese or Latin Extended.
- **Variable fonts** replace three or four static weight files with one.
- **`font-display: swap`** shows a system font until the custom one is ready, so a slow font doesn't block the text.
- **Self-host.** Then `preconnect` to the font domain so the handshake happens early.

## 6. Reduce JavaScript

JavaScript was 10.2% of bytes, but it is the most expensive 10%: every kilobyte takes bandwidth to download, CPU to parse, memory to hold and battery to execute, multiplied across every visitor's device.

- **Pre-render HTML** with Astro, 11ty or Hugo instead of shipping a single-page framework for a marketing site that doesn't need one.
- **Audit with Chrome DevTools' Coverage panel.** Delete the libraries that run on one page in ten.
- **Defer non-critical scripts** (analytics, chat widgets, embeds) until after the main content paints. Google Tag Manager alone ships 50 to 80 KB before it loads anything useful.

## 7. Enable gzip or Brotli compression on text

HTML, CSS and JavaScript compress by 60 to 80% in transit when the server turns gzip or Brotli on. It's a configuration setting, not a code change, and on modern hosts it is usually on by default. On older cPanel setups it isn't.

Check: run your site through [PageSpeed Insights](https://pagespeed.web.dev/). It flags "Enable text compression" against every uncompressed asset. On a WordPress site, your host's control panel or a one-line `.htaccess` entry fixes it in minutes.

## 8. Purge your unused CSS

A production CSS file should be small. Tailwind's compiled output on an OakFox marketing site typically comes out at 5 to 15 KB gzipped because unused classes are purged. If your site's production CSS is larger than its HTML, something has gone wrong.

- Run PurgeCSS, or your framework's built-in equivalent, as part of the build.
- Delete legacy stylesheets left over from previous themes.
- Avoid full icon fonts when an inline SVG does the same job for a tenth of the weight.

## 9. Cut the third-party scripts you don't need

Analytics, cookie banners, chat widgets, map embeds, tag managers: all third-party, all count as your page's emissions.

- Swap Google Analytics for cookie-free analytics (which also removes the banner).
- Load chat widgets only when a visitor opens them, not on every page.
- Embed maps as a static image with a "View on Google Maps" link, not live iframes.
- Delete one script a month until something visibly breaks.
